# KNOWN-GAPS — lacunas conhecidas e classificadas

| # | Lacuna | Classificação | Mitigação planejada |
|---|---|---|---|
| G1 | `RetroDECK/components` não clonado integralmente (timeout por blobs pesados; 5.516 paths só em `archive_later/`) | **Análise parcial** — modelo compreendido por amostragem (framework + duckstation + es-de) | Clonar com `--filter=blob:none --sparse` em máquina com rede melhor antes da Fase 4 (adapters) |
| G2 | EmuDeck: apenas ramo principal analisado; `android/`, `chimeraOS/`, `darwin/` não auditados em profundidade | **Fora de escopo v1** (alvos não-Linux-desktop) | Registrar; revisitar se houver demanda |
| G3 | PhaseZero lado Windows (`bootstrap-tools.ps1`, ~16k linhas) auditado por documentação (`CLAUDE.md`) e amostragem, não linha a linha | **Análise dirigida** — padrões de resiliência (checkpoint, change manifest, rollback, disk guard) confirmados pela doc interna e testes | O Unified é Linux-first; o lado Windows serve como referência conceitual, não como fonte de código |
| G4 | Nenhum teste dinâmico executado (nenhum script dos quatro projetos foi rodado) | **Restrição da Fase 0** (proibido mutar estado) | Fase 1+: bancada de testes com injeção de falhas |
| G5 | Nenhuma validação em hardware Steam Deck (LCD/OLED/dock) | **Bloqueador para "READY FOR IMPLEMENTATION" pleno** da parte Deck-específica | Matriz §13.4; depende de Q6 (OPEN-QUESTIONS) |
| G6 | Comportamento real do cloud sync EmuDeck (rclone) não exercitado; análise só estática de `cloudServicesManager.sh`/`cloudSyncHealth.sh` | Análise parcial | Prototipagem descartável na Fase 3 |
| G7 | Licenças de assets (ícones, artes, templates de controle) dos projetos de referência não inventariadas item a item | Pendência legal | 11-legal/THIRD-PARTY-NOTICES lista os blocos conhecidos; inventário fino antes de redistribuir qualquer asset |
| G8 | Versões exatas de SteamOS/Steam Client para a matriz de compatibilidade (§11.5) não levantadas | Pendência de pesquisa operacional | Levantar na Fase 2 com hardware real |
| G9 | PhaseZero não tem arquivo LICENSE | Pendência legal (Q2/Q3) | Decisão do titular antes de qualquer reuso formal |
| G10 | Requisitos de acessibilidade (narração/screen reader em Game Mode) sem solução técnica validada em Godot | Pesquisa pendente | ADR-0002 exige protótipo com critérios mensuráveis na Fase 5 |
| G11 | Boot direto/autologin da sessão Game Mode não validado com snapshot+console de recuperação | Bloqueio operacional G7 | Sessão manual SDDM e fallback Plasma existem; não tocar em GRUB/SDDM default antes do protocolo físico |
| G12 | Escala de texto do host (`forceFontDPI` do Plasma) não é honrada pela UI | **Lacuna de acessibilidade** — `reducedMotion` e `highContrast` já vêm do host via `dashboard.accessibility`; a escala não | O QML fixa `font.pixelSize` em ~72 pontos só no `Main.qml`, mais `Emulation.qml` e `SteamGameplay.qml`; aplicar escala exige um helper de tipografia e reexecução dos harnesses de layout/foco. Não foi feito junto do alto contraste para não misturar mudança de layout com mudança de cor às vésperas de uma release |
| G13 (QML-HARNESS-MIGRATION) | Dez harnesses QML antigos (`check_handheld_shell`, `check_main_emulation`, `check_emulation`, `check_steam_gameplay_responsive`, `check_handheld_layout_focus`, `check_main_handheld_sections`, `check_credentials`, `check_credential_dialog_responsive`, `check_high_contrast`, `check_packaged_assets`) ainda rodam sob `qml6` com `skipif` | **Legado tolerado, não é gate** — um `skip` produz suíte verde num host onde nada visual foi verificado, que foi como a regressão de ícones da a37 atravessou | Convertê-los para o harness próprio do projeto depois do VS-03. Enquanto não converterem: não contam como gate, e nenhum teste novo da vertical slice pode usar `skip` (o `check_scene_text` já reprova com `QML-VISUAL-ENVIRONMENT-001`). O job `qml-visual-linux` do VS-03 reprova quando Qt ou captura estiverem indisponíveis |
| ~~G14~~ | ~~Baselines visuais não versionadas: o texto usava a Liberation Sans do SISTEMA~~ | **FECHADA em 2026-07-28** (`1d9a52e` + `6fb2a75`) | A causa era mais funda que a suposta: não bastava empacotar a fonte, porque a do SISTEMA sombreava a empacotada mesmo com o arquivo certo carregado (`contentWidth` 320.08 → 323 ao isolar). O harness passou a isolar o fontconfig na fixture, e as dez baselines foram geradas nesse ambiente |
| G15 | `accessibilityGeneration` existe e está mapeada em `GENERATION_BY_KIND`, mas nenhuma propriedade real a consome | **Infraestrutura pronta, consumidor ausente** — a invalidação seletiva por perfil de acessibilidade não pode ser declarada como gate funcional enquanto nada depende dela; um consumidor artificial criado só para o teste passar provaria apenas que o teste passa | Fechar junto da entrega de acessibilidade (`textScale`, `reducedMotion`, `highContrast` consumidos por token ou setting real). Até lá: `accessibilityGeneration infrastructure: ready`, `accessibility-dependent property: not implemented`, `selective accessibility invalidation: deferred` |
| G16 | `test_cli_emulation.py::test_controls_cli_plan_apply_status_and_rollback` reprova de forma intermitente no CI | **Intermitência pré-existente, não diagnosticada** — reprovou no Python 3.12 enquanto 3.11 e 3.14 passavam no MESMO run; passou 3/3 localmente e no rerun. "Flaky" é rótulo, não diagnóstico: a causa não foi encontrada | Investigar em entrega própria. O caminho `controls plan` → `apply` usa `planId`/`confirmToken` com validade, e a hipótese é expiração ou colisão de estado XDG entre testes — não confirmada. Não foi corrigida junto do HOST-ACTIVATION-01 para não misturar escopo |
| G17 | `steamzero service status --json` não existe — devolve `E-CLI-USAGE: ação desconhecida` | **Lacuna de contrato, não bloqueante** — a convergência do daemon é observável pelo alvo de `/opt/steamzero/current`, pela resposta estruturada de `service refresh --expect-release`, pelo estado do socket, pelo `doctor` e pelo status do gerenciador host | Entrega própria. Não foi acrescentado durante a operação de release da a38 para não misturar escopo novo com certificação de artefato |
