## 4. Experiência do usuário — pontos que precisam revisão

Este é o eixo mais negligenciado do projeto: o código está bem testado e a
comunicação com o usuário, não.

**Padrão recorrente encontrado nesta sessão: o erro anuncia a causa errada e
sugere uma ação que não resolve.** Três exemplos, dois já corrigidos:

1. Drift de commit dizia "componente degradado" e oferecia "reparar" — que na
   prática é *downgrade* de um emulador que funciona. Corrigido (`ca69b2a`).
2. Core libretro sadio recusava launch com `E-COMPONENT-DEGRADED`, convidando o
   usuário a reparar uma instalação perfeita. Corrigido (`680b17c`).
3. Resposta acima de 1 MiB saía como "Versão de contrato incompatível. Atualize
   o cliente ou o servidor" — atualização nenhuma resolve. Corrigido (`680b17c`).

**Vale auditar o catálogo inteiro de erros com essa lente**: para cada código,
a `probableCause` é mesmo a causa provável, e a `manualAction` resolve? Suspeito
fortemente que há mais casos. `docs/ERROR-CATALOG.md` agora tem dono declarado
em `SZ-AGG-CORE`.

**Outros pontos:**

- A ação "reparar" precisa dizer o que vai fazer. Convergir ao pin pode

## 5. Tema — maturidade real

A fonte normativa é `docs/01-product/THEME-ENGINE-AND-STUDIO.md` §2, que é
honesta. **Leia AURA-SURFACES.md antes de tocar em qualquer coisa de tema**: são
quatro capacidades INDEPENDENTES (AURA UI, AURA Launcher, Theme Engine, Theme
Studio) e provar uma não promove outra.

Existe hoje: manifestos, tokens, herança, resolver, fallback, temas builtin,
catálogo, instalação/importação, preferência, preview e edição de
tokens/metadados com exportação, contratos parciais de scene graph e projeção
QML, effect stack allowlisted em `MediaEffectLayer.qml` (blur, cor, saturação,
brilho, contraste, sombra, glow, opacidade, máscara, vignette, reflexão).

**Não existe como produto concluído:**

- scene graph livre consumido ponta a ponta;
- grafo visual de efeitos;
- timeline;
- transformações completas de logo a partir de um único asset;
- extração dinâmica de cores;
- cache GPU com orçamento;
- canvas de autoria (o Studio hoje é **somente leitura**);
- certificação física.

A filosofia normativa é **"renderize, não edite"**: o pacote guarda o
asset-fonte e uma receita declarativa. Não aceite múltiplos assets pré-editados
como substituto de uma capacidade da engine — é a forma mais fácil de fingir
progresso aqui.

Ondas 1–5 (contrato de scene/effect/image, transformações de asset único e
cache, layouts/repeaters/bindings/breakpoints, extração de cores e glass por
tiers, states/timeline/transições) precedem 6–8 (componentes do Launcher, OSD,
save gallery; Studio canvas/árvore/inspector; Studio effect graph/timeline/
profiler). O `nextAction` atual do item aponta para a onda 6/7.

Restrição de segurança que não pode ser flexibilizada: tema de terceiros não
executa QML, JavaScript, Python, shell, binário, biblioteca ou shader
arbitrário. Só scene graph, bindings, componentes e effect nodes allowlisted.

Toda afirmação de desempenho (FPS, memória, frame time) exige medição no
hardware e na release indicados — `tools/theme_perf_probe.py`, com alvo de p95
≤ 16,7 ms, startup ≤ 2 s e ≤ 512 MB. Nunca inferir de teste offscreen.
