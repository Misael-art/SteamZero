- 2 jobs `media.global` em `running` desde 2026-07-26; `JobManager.recover()` existe mas **não é chamado no bootstrap**.
- `doctor` reporta `ok` (falso verde): seu único check de recovery (`_pending_operations`, doctor.py:28) conta journals, **não jobs** — jobs stalados em SQLite passam despercebidos.

## Mudanças (com ponto de inserção exato)

### 1. `src/steamzero/jobs/models.py` — máquina de estados
- `VALID_TRANSITIONS["interrupted"]` hoje = `{queued, rolling-back, completed}` (linha 26). Para D1 (cancelar-e-marcar sem reenfileirar), adicionar `"cancelled"` ao conjunto de destinos de `interrupted`, permitindo `interrupted -> cancelled`. Isso evita o caminho `queued` (que reativaria rede).

### 2. `src/steamzero/jobs/manager.py` — `recover()` (linha 293) e `cancel()` (linha 194)
- **`recover()` (D1):** no branch sem `operation_id` (hoje linha 308-309 faz `queued`), trocar por: `self._transition(job, "cancelled")` + `job.error_code = "recovered"` (campo já existe no modelo, linha 55) e persistir. Job stalado sem operação termina `cancelled` marcado — não re-dispara rede.
- **`cancel()` (D2):** no branch `running` (linha 202-203), quando **não há runner vivo** (detecção: o controle in-memory `_controls[job_id]` não existe / não foi consumido — o manager não registra handler ativo para jobs recuperados pós-reboot), forçar caminho terminal via `recover()`: transitar `running -> interrupted` e resolver. Quando há runner vivo (controle presente), manter `request_cancel` atual (sem regressão). Adicionar erro público `E-JOB-NO-RUNNER` para o caso de cancelar algo que não pode ser resolvido, satisfazendo A42 ("terminal ou erro específico").

### 3. `src/steamzero/service/core.py` — `serve()` (linha 441-444) — D3
- Dentro do bloco `with StateStore() as store:` após `store.migrate()` (linha 444), chamar:
  - `JobManager(store).recover()` (jobs running → terminal) e
  - `transaction.recover_all()` (journals/órfãos sem job).
- **Wrap try/except** (AGENTS.md §8 — falha degrada, nunca trava): capturar, logar (módulo de logging existente) e registrar causa para o doctor ver; **nunca impedir `serve_forever`**. Recovery é best-effort no boot: o daemon precisa subir mesmo se recovery falhar.

### 4. `src/steamzero/diagnostics/doctor.py` — `run_doctor()` (linha 39) — elimina falso verde
Adicionar 4 checks novos, cada exception-safe (padrão try/except → `_check(..., "fail", ...)` já usado):
- `jobs.stale`: count de jobs `running` via `StateStore.list_jobs(states=["running"])`; `warn` se >0.
- `operations.consistency`: operation row state vs. journal terminal (inconsistência).
- `staging.orphan`: dirs de staging sem operation row (reusa `paths.staging_for`/`staging_dir`).
- `journal.orphan` / `backup.orphan`: journal/backup sem referência no DB.
Inclui os contadores no `data` retornado (linha 124-130), como `pendingOperations` já é incluído.

- **§8 (falha nunca trava):** recovery no bootstrap envolvido em try/except; daemon sobe mesmo se recovery falhar. Teste dedicado.
